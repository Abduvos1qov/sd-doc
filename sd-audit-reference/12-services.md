# 12 — Services

Cross-cutting capabilities that aren't part of any single feature.
All registered in `injection_container.dart` and consumed by BLoCs.

## Location stack

Three layers, each progressively more app-specific:

```
GeoLocator package
    │
    ▼
LocationService                  (~134 lines)
    │  start(), stop(), Stream<Position>
    ▼
LocationSenderService            (~105 lines)
    │  batches positions, POSTs to /api3/auditor/gpsTrack
    ▼
MainLocationService              (~22 lines)
    │  start() / stop() façade
    ▼
DashboardBloc, MerchandiserBloc
```

### `LocationService`

`lib/features/sd_audit/core/services/location_service.dart`. Wraps
`geolocator`:

- Requests permission (`Permission.locationAlways`).
- Checks GPS service is enabled (`Geolocator.isLocationServiceEnabled`).
- Exposes a `Stream<Position>` via `Geolocator.getPositionStream`
  with a configured accuracy and distance filter.
- Calls `InsertLocationUsecase` for each position so the SQLite GPS
  table fills up.

### `LocationSenderService`

`lib/features/sd_audit/core/services/location_sender_service.dart`.
Runs a `Timer.periodic` (~ every minute):

1. Read first 20 rows from `TrackGpsDataSourceImpl`.
2. If non-empty and connectivity exists, POST batch to `gpsTrack`.
3. On 2xx, delete the 20 rows; otherwise leave them for retry.

This pattern is robust against transient outages — rows stack up,
nothing is lost. It's why GPS uses SQLite, not ObjectBox: append
volume is high, batch-delete semantics are clean.

### `MainLocationService`

Tiny façade that starts/stops both services together. Injected into
`DashboardBloc` (and `MerchandiserBloc`) so the screen owns the
lifecycle.

Calling pattern:

```dart
// In DashboardBloc:
on<DashboardInitialEvent>((event, emit) async {
  await mainLocationService.start();
  // ...
});

on<LogOutEvent>((event, emit) async {
  await mainLocationService.stop();
  // ...
});
```

### Permission flow

`PermissionStatus` is checked at start. If denied or permanently
denied, the BLoC emits an error state surfaced as a snackbar +
"Open Settings" deep-link via `permission_handler.openAppSettings()`.

## Background service

`lib/common/background_service/` and the `flutter_background_service`
package.

Initialised in `main()` before `runApp` (kept on through the lifetime
of the process). Used to keep GPS sampling alive while the app is in
background — necessary for "track agent movement" use cases.

`location_accuracy_checker.dart` returns the configured `LocationAccuracy`
constant based on `ConfigBox` (which the server pushes at sync). If
the server says "high accuracy", you get `LocationAccuracy.high`;
default falls back to medium.

The background ISO platform configuration lives in
`android/app/src/main/AndroidManifest.xml` (foreground service
permission) and `ios/Runner/Info.plist` (background mode for
`location`). When adding new background work, both manifests need
edits or it silently won't run.

## App version manager

`lib/features/sd_audit/core/services/app_version_manager.dart`. Owns
the version-check lifecycle:

1. On call, hits `EndPoints.checkUpdateVersion` (`/app/audit`) with
   the device's current version (`package_info_plus`).
2. Parses the `UpdateVersion` entity (force, recommended, latest
   version string).
3. Writes flags into `GeneralBox`:
   - `version_force_update`
   - `version_recommend_update`
   - `last_update_version`
   - `last_version_check_time`
4. Calls `context.showUpdateVersionDialog(...)` with the right mode
   if a prompt is due.

Throttled — `last_version_check_time` prevents re-checking too often.

A recent change (see commit `665a0ed`) wired this into the post-sync
flow so the first dashboard load after a sync may pop the update
dialog. Tracked in the `version_*` Hive keys.

## Routing helpers

`lib/features/sd_audit/core/services/routing/`

Two helpers, both about route presentation, not URL routing:

- `bottom_sheet_route.dart` — `BottomSheetRoute<T>` extending
  `PageRoute<T>`, used by `showBottomSheet`-style modals that need
  named routing behavior.
- `material_with_modal_page_route.dart` — page route variant that
  preserves the `MaterialPageRoute` transition while permitting modal
  overlay above the page.
- `osrm_routing_service.dart` — external API call to OSRM
  (`http://router.project-osrm.org` or self-hosted) for turn-by-turn
  routes between two coordinates. Caches results in-memory; debounces
  rapid recomputation. Consumed by visit-map widgets.

## Firebase

Initialised in `main()` from `firebase_options.dart` (generated by
`flutterfire configure`):

```dart
await Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform);
```

The wiring:

| Package | What it does in sdaudit |
|---|---|
| `firebase_core` | Setup |
| `firebase_analytics` | Imported; minimal event recording |
| `firebase_crashlytics` | Receives `FlutterError.onError`; uncaught exceptions auto-report |
| `firebase_messaging` | Receives push tokens; used by `getKnowledge` endpoint and possibly for sync wakeups |
| `cloud_firestore` | Imported; small use case (chat-like fallbacks); audit before relying on it |

The hookup is in `main.dart`:

```dart
FlutterError.onError = (details) {
  FlutterError.presentError(details);
};
```

A more complete Crashlytics setup typically also pipes platform errors
(`PlatformDispatcher.instance.onError`) to `recordError`; this app
doesn't. That means Dart-native uncaught async errors won't surface in
the Crashlytics console.

## Phoenix (app restart)

`flutter_phoenix` wraps the root widget:

```dart
Phoenix(child: const MyApp())
```

`Phoenix.rebirth(context)` rebuilds the whole widget tree. Used after
logout to drop all BLoC state without manually closing every BLoC.
Important caveat: `Phoenix` rebuilds widgets but **does not reset
`getIt`** — lazy singletons (use cases, data sources) persist. State
held in them (rare) carries over.

## What's not a service

A few things that look like services but aren't:

- `NetworkInfo` (in `core/network/`) — registered as a `lazySingleton`
  but it's just a connectivity wrapper, not a service in the runtime
  sense.
- `HttpClient` — see [`09`](09-networking.md). Stateless wrapper around Dio.
- `ChuckerFlutter` — debug-only navigator observer, not a service.
